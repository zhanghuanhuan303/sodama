结论：本版内核（eBPF 数据面 + reactor 池 + 缓冲池/回收）在全部五个压力阶段都是五方中内存占用最低的实现： idle 27–28.5 MB（对手 43.4–60.2 MB）；hold 为 dae 的 1/10、其余对手的 1/3–1/6； churn 后仍 ≤31.2 MB（对手 92.7–494.8 MB）；UDP 29.2 MB（对手 55.7–64.5 MB）； 静置回收后 12.5 MB（对手 68.4–317.7 MB）。 两遍独立复测的关键数字一致（偏差 ≤3%），作为本版内存终测口径收口。

02 · 方法与口径

  • 拓扑：client ns — 网关（被测实现）— WAN ns（bench_io 全双工 echo 1.1.1.1:8080 + sing-box VLESS 上游 10.9.9.2:8543），与 lab/perf/run.sh 同一套夹具。
  • 实现姿态：sodama/dae 以各自原生 eBPF 数据面（生产模式）接管；sing-box/v2ray/mihomo 以各自 Linux tproxy 模式 + nft 规则接管（mihomo 配置需 allow-lan: true + bind-address: "*"，默认 loopback 绑定无法承接透明流量——已在 lab/perf/mihomo.*.yaml 固化）。
  • 阶段：idle（启动后 3–6s）→ load（VLESS 4 流 ×128 MB 全双工 echo）→ hold（2000 条并发，每条 32B ping 验证后持有 10s）→ churn（10s 限时 connect→ping→close，约 26k 条）→ recovery（全部关闭后静置 30s 读一次 RSS）。
  • 指标：每阶段对被测进程 200 ms 采样 /proc/<pid>/status 的 VmRSS / Threads 与 /proc/<pid>/fd 计数，取峰值；recovery 为静置后的单次读数。
  • 样本：五方 × 两遍独立全程（/tmp/mem-results.tsv / /tmp/mem-results2.tsv）；负载均由客户端侧验证（hold 2000/2000 全成功，churn ≈26 228 条/10s，吞吐 verify=ok）。
  • 已知偏差：dae 的 load 轮出现尾读截断（512 传 / 502 收，verify=ok），峰值采样仍有效；v2ray 的 recovery 两遍差异大（190 / 318 MB），与其 GC 时机相关；RSS 为进程视角，不含内核侧内存（五方共用同一内核路径，可比）。
口径与边界（第三方评审后更新，2026-10-05）：本报告为进程 VmRSS 口径，不含内核侧（slab/socket/pipe/skb/eBPF map） 与系统总内存。事实核对初测显示空闲 hold 的内核侧 slab 增量可达 ≈46 KB/连接（可能大于用户态 ≈15 KB/连接）， 因此「内存最低」的结论仅限用户态口径。系统内存四层模型基准（Process → Kernel → Total → Resource/连接） 与 FD 架构治理已列入下一版：见 docs/reviews/2026-10-05-adoption-proposal.md（I1–I5）。

06 · 生命周期与回收

  • 静置回落：load/hold/churn 后静置 30s，sodama RSS 由峰值 31.2 MB 回落到 12.4–12.5 MB（低于启动期 27–28.5 MB 的一次性高水位）；对手同口径 68.4（mihomo）/76.8（sing-box）/81.7（dae）/190–318（v2ray）MB。
  • 缓冲池封顶（O8）：转发缓冲池 64/128 KB 两档、按字节封顶 8 MB；UDP 槽按需增长；churn 300 条长连接 RSS 27.3 → 23.9 → trim 后 23.3 MB，无增长。
  • 周期 trim：30s 一次 malloc_trim，把 allocator 空闲页还给内核（本报告 recovery 数据即其效果）。
  • 优雅退出：SIGTERM 有界退出——50 条在途连接整机 462 ms（内部有界 302 ms），退出后 TC 钩子/管道无残留。

07 · 观察与下一版可做的内存优化

#观察下一版候选动作
1hold 2000 峰值 fd 16 087（≈8/连接，五方最高；sing-box 6、mihomo 4、dae/v2ray 2）——reactor 每条连接持有 2 条管道（4 fd）+ client/upstream 两个 socket评估管道池/复用（同 worker 内复用预建 pipe pair）或减少 fd 的 splice 变体；先做收益/语义评估（SPLICE_F_NONBLOCK、半关闭、错误路径）
2启动期一次性高水位 27–28.5 MB（稳态 12.5 MB）把启动期一次性缓冲（订阅/规则编译）纳入池化或复用；或在 status 里暴露 allocator 高水位便于观测
3churn 期短命 prelude 线程把线程峰值抬到 42（常驻 29）观察是否需要把 prelude 并入池/预算；低优先（不影响稳态）
4dae/v2ray 在 hold/churn 后高水位不回收（数百 MB）非 sodama 问题，作为对照记录；验证 sodama 缓冲池在更高压力（50k+ 连接）下仍单调有界（可加进 soak 夜间项 G5）
