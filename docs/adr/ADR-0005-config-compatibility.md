# ADR-0005：配置——100% 兼容 .dae，语法收回仓库

- **状态**：已采纳（2026-10-03）
- **对应决策点**：D5
- **相关**：ADR-0007（优先级）、主文档 2.4

## 背景

`.dae` 是 dae 的用户接口，也是订阅/面板/文档生态的契约。现状：

- 语法定义在**仓库外**：`dae-config-dist/dae_config.g4`（ANTLR 语法），本仓库只有生成物与 walker（`pkg/config_parser/`，839 行 + 366 行测试）；
- 配置段：`global / subscription / node / dns / group / routing`（+ `include`），支持 include 合并、默认值、patch、outline 导出；
- 语义复杂度集中在：include 路径安全（必须位于入口配置目录之下）、合并冲突、大小写/通配、NOT 归一化、规则集合函数。

## 选项

| 选项 | 说明 |
|---|---|
| A 新格式（TOML/YAML）+ 迁移工具 | 实现简单，破坏生态 |
| B 兼容 + 新格式双轨 | 两条路维护 |
| **C 100% 兼容 .dae（采纳）** | **复刻既有语义，语法收回仓库，schema 文档由代码生成** |

## 决策

采用 C，并附三条工程约束：

1. 解析器用 `logos`（词法）+ 手写递归下降（或 `chumsky`），**不使用 ANTLR 运行时**；错误信息带源码 span（`miette`）；
2. 把 `.g4` 的语法语义**收回本仓库**（作为 Rust 解析器的规格与测试语料来源），消除「语法在外部仓库」的漂移；
3. 提供 `--emit-schema-docs`，让配置文档与代码同源；`validate` / `export` 子命令与 Go 版**逐字节对拍**。

## 理由

- 配置 + 路由是唯一**无需 root、可用 Go 版逐条对拍**的模块 —— 兼容反而降低了验证成本（随机生成配置 → 两边解析 → 比对归一化输出）。
- 用户迁移成本为零，是「分批交付」策略能成立的前提（P1 落地后即可真实使用）。
- include/merge/patch 的既有语义是用户依赖的行为，重新发明格式等于把兼容性风险推给用户。

## 后果

- 正面：P1 可独立验收；`validate`/`export` 天然成为后续所有模块的对拍工具。
- 负面/代价：必须复刻既有语义（含怪癖），不能「顺手改好」；需要建立语料库（真实世界的配置文件 + 边界用例）来防止回归。
- 需注意：ANTLR 的错误恢复行为与手写解析器不同，错误信息可以更好，但**接受/拒绝的集合必须一致**（否则会出现「Go 能过、Rust 不能过」）。

## 验证方式

- 语料对拍：仓库内 `example.dae` + 自造边界用例（include 越界、重复定义、NOT 嵌套、空 section、Unicode 域名）；
- 差分测试：同一输入两边解析 → 归一化 AST/JSON 逐字节比对；
- Fuzz：`cargo-fuzz` 打解析器，保证不 panic（Go 侧历史上用 recover 兜 ANTLR 的错误恢复，见 `config_parser.go`）。

## 修订条件

若上游 `.g4` 发生不兼容变更，或社区明确接受新格式，新写 ADR 处理迁移。
