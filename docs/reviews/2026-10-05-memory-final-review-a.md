# 第三方书面评估（A）——内存终测报告

> 存档说明：以下为第三方书面评估原文（用户转贴），仅做排版整理；观点不代表本项目立场。
> 评审对象：`docs/memory-report.html` v1.0（五方内存终测，2026-10-05）。工程方回应见 `2026-10-05-adoption-proposal.md`。

这份内存终测报告的数据非常亮眼，sodama 在内存足迹（Memory Footprint）和并发伸缩性上展现出了极高的工程质量，
尤其在与目前主流代理内核的横评中具有压倒性优势。通过 eBPF 数据面、Reactor 池化和主动回收机制的结合，
sodama 达到了非常苛刻的轻量化标准。

以下是对这份测试报告的技术审查、亮点拆解以及针对下一版优化的建议：

## 1. 核心亮点与架构验证

- **Reactor 模型大获成功**：`SODAMA_NO_REACTOR=1` 的单变量对照非常有说服力。将 20,012 个线程（527.4 MB）
  压缩到 29 个线程（34.8 MB），15 倍的内存收益和 690 倍的线程开销缩减，完美证明了基于事件驱动的
  Reactor 池是高并发网络 I/O 的唯一解。
- **出色的内存回收（GC）策略**：静置 30s 回落至 12.5 MB（甚至低于启动期的 27 MB）是全场最佳表现。
  主动调用 `malloc_trim` 把空闲页强制还给 Linux 内核，直接击中了 Go 语言系（v2ray, mihomo, sing-box）
  GC 策略保守、释放不积极的软肋，也优于同为 eBPF 派系的 dae。
- **防爆栈与稳态控制**：在 26k conn/s 的极端 Churn 场景下，内存仅从 29 MB 涨到 31.2 MB，说明你的
  8MB 封顶缓冲池（O8）和零拷贝/复用机制起到了决定性的屏障作用，没有发生内存泄漏或碎片化。

## 2. 隐藏的代价：FD 爆炸与内核内存（盲区提醒）

在报告第 07 节观察 1 中，提到了 hold 2000 峰值 fd 16,087 (≈8/连接)。这是一个必须在下一版高度重视的隐患。

虽然报告在「已知偏差」中坦诚了 RSS 不含内核侧内存，但在 splice 零拷贝的实现中，内核内存的消耗是不容忽视的：

- **Pipe Buffer 开销**：每次 splice 需要一对 Pipe。如果 2000 个连接占用了 16,000+ 个 fd，意味着有大约
  8,000 个 pipe 端点。Linux 中每个 pipe 默认分配 16 个页（64 KB）的内核环形缓冲区。在不修改 pipe 容量
  （`fcntl(fd, F_SETPIPE_SZ, size)`）的情况下，2000 个连接在内核中可能吃掉了数百 MB 的 Slab 内存。
  这些内存在 VmRSS 中是隐形的，但对整机物理内存是实打实的占用。
- **系统级瓶颈**：单连接 8 个 fd 意味着在默认 `ulimit -n 65535` 的机器上，sodama 最多只能承载
  8,000 个并发连接就会报 Too many open files，这削弱了 Reactor 模型本该带来的高并发红利。

## 3. 下一步优化的优先级评估（针对 Section 07）

- **最高优先级（动作 1）：Pipe 池化或替代方案**。绝对值得投入精力做 Pipe 预建和复用（Pipe Pool）。
  在同一个 worker 内复用 Pipe Pair 进行 splice 转发，可以把单连接的 FD 数量从 8 个直接降回 2 个
  （仅保留 Client 和 Upstream Socket）。这不仅能解决 FD 枯竭问题，还能避免高频建连/销毁时的
  `pipe()` 系统调用开销，大幅降低内核 Slab 内存占用。
- **中优先级（动作 4）：长期 Soak 测试**。加入夜间 G5 甚至 72 小时的超长 Soak 测试（持续微量 Churn +
  随机长连接）。`malloc_trim` 虽然好用，但高频的小内存分配依然可能导致底层 glibc/jemalloc 的内存碎片化，
  长期跑才能验证「单调有界」。
- **低优先级（动作 2 & 3）：启动水位与短命线程**。启动期的 27 MB 峰值（规则编译/订阅拉取）和
  Churn 期的 42 线程峰值属于「可接受的瞬时脉冲」。在不影响稳态（12.5 MB / 29 线程）的前提下，
  为了这十几 MB 去重构池化预算的 ROI（投入产出比）较低，建议延后。

## 4. 测试夹具与方法论

测试环境的设计（Network Namespaces 隔离、bench_io 全双工、tproxy vs eBPF 控制变量）非常严谨，
规避了同机环回口的 TCP 栈短路问题。采用 `/proc/<pid>/status` 高频采样结合 SIGTERM 优雅退出的观测闭环，
作为一份终测报告，其数据可信度极高。

## 总结

这个「轮子」不仅造出来了，而且在数据面上达到了顶级性能。下一版（v1.1 或 v2.0）只需把 splice 依赖的
Pipe FD 开销打下来，sodama 的内存管理就真正做到了无死角的「遥遥领先」。
