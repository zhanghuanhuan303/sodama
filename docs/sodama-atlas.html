三条口径声明（先读）

  1. 本机吞吐的口径：lab 拓扑在历史各轮默认开启网卡 offload；v1.x 时代新 lab 曾无条件关闭 dae0/dae0peer offload（会把标准代理路径砍半），该动作已收进 L3 用例，现为默认口径。
  2. 「修复后值」的标注：vless 17.3 G 与 ss 9 265 是 2026-10-16/17 修复轮之后的值； 未复测的路径（TLS）沿用同轮实测值。每次数字都标来源。
  3. 公网轮与生产不是同一件事：公网轮（§4.5）测的是「客户端效率」，节点出口带宽是共同天花板； 生产（§8）测的是「长期稳态有没有界」。

§1缘起 · 三个研究问题

  1. 数据面能不能整段换成 Rust eBPF？——dae 用 C 写 eBPF（4 400 行）+ Go 控制面；本项目押注 Rust 生态（aya + Rust→BPF），代价是 CO-RE/BTF/verifier 的硬约束要逐个趟。Rust→BPF 工具链（nightly + bpf-linker）对内核版本与对象格式的要求比 clang 路径更窄：C 侧 4 400 行译到 Rust 的同时，还要在宿主（6.18）与生产（6.12）两类内核的 verifier 上都通过。
  2. 换语言能不能同时换掉「每连接一线程」？——Reactor（epoll + splice 零拷贝 + codec 状态机） 把每连接线程成本降为 0 线程，代价是编解码路径要自己写 WS/VLESS/ss 帧层。
  3. 能否做到「可验证」而不只是「能跑」？——跨实现逐字节对拍、内核级用例矩阵、 真实节点公网轮、72h 生产轮；每个数字都带口径与出处。「带口径与出处」落实为 §5.3 的七条口径纪律与 §9.3 的数据源索引：任何数字都能指到某轮的 TSV 或日志。

押注的结果：数据面 24 程序 / 28 map（≈95% 对齐 dae），用户态全 Rust（12 协议家族）， 生产连续多轮 72h 量级验证。这条路径的代价与边界都写 §6/§7。

§3架构总览 · 四层分解

  1. eBPF 数据面（24 程序 / 28 map）：LAN/WAN 双钩子、五角色 × L2/L3 变体、conn_state 双 epoch、redirect_track、domain_routing 域位图、routing_handoff 首包交接、 ringbuf 事件、trace_filter_map 内核侧过滤、offload 记账（fentry/kprobe）、XDP 计量。
  2. Reactor 用户态（每连接 0 线程）：epoll 事件循环 × N worker，每 worker 独立投递通道 + 轮询定向分派 （2026-10-17 修 ss 双峰回归）；splice 零拷贝（明文路径）+ codec 状态机（AEAD/WS/VLESS 帧层）；管道池与 fd 预算治理。「独立投递通道 + 定向分派」替代共享队列 drain-all 认领：后者会让单 worker 领走全部连接，在 ss 上退化为单核 AEAD 瓶颈、吞吐双峰（踩坑 5）。
  3. 控制面：配置即唯一事实来源（config.dae），inotify 热驱动 + 双 epoch 原子切换； 订阅周期刷新与负缓存；DNS 控制面（多上游/路由/ECS/缓存）；组健康探测（活跃/空闲退避 + 墙钟看门狗）。
  4. 观测面：status --json（traffic / real_domain / stats / offload_* / xdp / sysctl / trace 等段）、 Prometheus metrics、状态 socket 控制命令、面板 v2.0、sysdump 现场归档。观测面按「人看什么」组织：面板给日常，status 给脚本，Prometheus 给长期存储，sysdump 给一次性的现场归档。

当期新增（相对 v1.x 叙事）：config-watch、1h 流量历史、real_domain_runtime、 --drain/--abort、UDP GSO、UDP full-cone 端点池/raw_udp、tls_fragment*、 pprof_port、bandwidth_max_*、sd_notify、CLI 取证五件套、面板 v2.0。

4.2 · 并发扩展与瓶颈排序

  • direct 64×1 MB 口径 38.7 Gbps（v3.0 时代 35.2）；VLESS 8×64 MB 15.2 Gbps（受修复前口径影响，修复后按 4.1 的新基线外推更高）。
  • relay（无加密用户态泵）8 流 20.1 Gbps（splice 零拷贝路径）。
  • 瓶颈排序（先撞到者）：单核 AEAD（ss）→ 用户态内存带宽（v2ray 类拷贝泵）→ TCP 栈/软中断； sodama 的两条快路径（direct / splice）把成本推到内核侧后就接近线速。「先撞到者即瓶颈」是一个可操作的判断法：依次抬高负载，第一条被压住的资源就是当期瓶颈——ss 在 9 G 处被单核 AEAD 压住，v2ray 在 10 G 处被拷贝带宽压住。

4.6 · 长稳与有界性

  • 本机 60 min：RSS +17.6% FAIL 判据（单次 4.5 MB 台阶，非持续泄漏形态； Slab +0.26% / SUnreclaim +0.88% / fd 无增长 / 零失败；RTT p50 中位 44 µs）——列为待 2–3 h 复测项。台阶 ≠ 泄漏：判据看稳态段斜率与窗口极差——单次分配台阶（一次性抬升）与持续增长（斜率恒正）是两种形态；72h 轮通过前不启用「bounded-memory」表述。
  • 生产 72h 链（软路由 2C/4G，真实负载）：旧轮 21.4 h 收口 —— dial_errors/stragglers 全程 0、 RSS 冷启 43.8 → 预热台阶后稳态 53.5 MB（14 h 窗口极差 3.66 MB、稳态斜率 −47.8 KB/h ≈ 0）、 FD 133（103–184）、线程 18、reactor_codec_sessions == conns_total； 新轮 2026-10-17 03:22 起跑 → 78.5 h 收口：平台段 RSS 66.7 MB（47–59 h 斜率 −0.01 MB/h ≈ 0）， 109 137 会话 / dial_errors 58（0.05%）/stragglers 0，ws 截断误报 0（旧轮 9 738）； 1 周轮 2026-10-20 10:09 起跑（见 §8.3）。新引擎轮冷启基线：RSS 54.6 MB / 线程 20 / fd 143——比旧轮高（功能面更大），属预期；对照曲线见 §8.2。

三条观察：① 代码量——Rust 去重代码为 C 的 41%，同角色单程序 522 vs 1 371 （Rust 入口自含逻辑；C 为桩 + 每角色一份 do_tproxy_*，758–1 444 insn）； 但 sk_skb（79 vs 64）与 fentry 记账（306 vs 147）Rust 反而更大——总量差异不能简单归因于语言。 ② 工具链差异（本轮最有价值的发现）——C 的 local call 直接编码目标（call <imm>，可静态还原）， Rust（bpf-linker）统一为 call -1 + R_BPF_64_32，重定位符号是 .text、 addend 不可从标准 ELF 工具读出 → 静态 ELF 无法回答「入口实际带多少代码」：只能取 「入口 + 全部 .text」上界（Rust 3 359 vs C 8 101 insn），或运行时看 verifier 的 xlated 长度。③ BTF/重定位——Rust BTF 小 58%（aya 只描述用到的 map/签名； C 经 vmlinux.h 保留大量内核类型），但重定位多 22%（map 引用密度：28 vs 23 map）。

边界：两侧业务逻辑不完全逐行等价（Rust 多 xdp、C 有 tcp/udp 分支差异）； 代码量差异反映源码组织与功能覆盖，不构成「语言性能」结论；栈为函数内静态近似 （verifier combined stack 含调用链，本项目曾在 528 B 超限后移 per-CPU scratch，见 ADR-0065）。

§5工程实践与方法论

5.1 · 三级验收：单测 / lab 专项 / 跨实现逐字节

单测（351）只证明函数级行为；lab 专项在 netns 真实拓扑里跑（双拓扑 × 九用例、嗅探 punt、 UDP full-cone、v6、DoH-h2、Vision XTLS 状态机、钩子生命周期……）；跨实现逐字节才证明「正确」—— 规则编译与 Go 版对拍 5/5、Vision 帧层与 Xray 夹具四模式逐字节、TLS 记录层与 Go/quic-go 互操作、 shadow-tls 三版交叉。第四级是真实世界：真实节点公网轮 + 生产 72h 链。级别即证据强度（成本也递增）：单测（秒级）＜ lab 专项（分钟级）＜ 跨实现逐字节（小时级）＜ 真实世界（天级）。缺一级就会留一类盲区——R11 加载失败正是「只跑 QEMU、未跑宿主」漏掉的。

5.2 · 夹具工程学

吞吐夹具（bench_io 48 MB×4 流全双工）、连接夹具（conn_scale hold/churn）、 回显夹具（万级连接）、UDP 冲击器、Vision 夹具（Xray 交叉）——夹具自身的缺陷会伪装成被测实现的问题 （历史上踩过：回显夹具 8 次读上限→大流误 RST；夹具有限带宽掩盖实现差异），因此夹具也入「跨实现对拍」范围。

5.3 · 口径纪律（七条，condensed）

  1. 每个数字带口径（机器、内核、拓扑、轮次、offload 状态）；
  2. 对照必须同轮同拓扑（跨轮漂移用双数据集交叉验证）；
  3. 「未做」写成「未做」，不写成「等效」；
  4. 时长要诚实（60 min ≠ 72 h，72 h ≠ 永久）；
  5. 数字异常先怀疑口径与就绪状态（dae 未就绪时的「假公网兜底」曾造出 24.6 G / CPU 0 的假读数）；
  6. 修复后必须复测并更新原始数字（本版把 vless/ss 的修复后值直接替换进表，而不是并列旧值）；
  7. 数据源可复算：报告与图集的每个数字都能指到某轮的 TSV/日志。

5.4 · 研究性重写的四条经验

① 语义对齐优先于实现对齐（配置语义、钩子角色、conn_state 生命期逐条对）；② 第三方实现是最强的测试标尺（跨实现逐字节、真实节点轮）；③ 数据面与用户态要能分开测（L3 用例、offload 口径、单路径性能都单独可测）；④ 把「口径」写进工具（lab 的 SKIP_NET_OFFLOAD、real.sh 的目标/出口固定、TARGET_EXPECT_BYTES 短传输判定）。
